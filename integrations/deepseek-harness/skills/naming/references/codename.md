# 内部代号与项目名（codename）：什么时候该有，怎么不翻车

> 用途：product 模式，命名对象是**内部代号 / 项目代号 / 版本代号 / 功能暗号**时。
> 关键差异：内部代号的目标函数**不是**"打动人"，而是**不泄露、不误导、不占用真名、能口头传**。
> 强度：**机构**＝公司公开文档；**经验**＝公开实践；**判断**＝本文推断。

## 0. 先问三个问题（任一为"是"才需要代号）

1. **需要保密吗**？未发布的产品/并购/新架构，代号是防泄露工具（对外只说代号，不说功能）。
2. **需要解耦吗**？同一个名字在不同团队/地区有歧义时，代号提供唯一标识（如版本代号）。
3. **需要团结吗**？短期项目需要情绪标记（内部士气），但这是**次要收益**，不能盖过 1 和 2。

三个都答"否" → **不要起代号**，直接用功能名（`billing-v2`、`export-rewrite`）。多加一层命名＝多加一层翻译成本。

## 1. 内部代号的四条硬规则

| 规则 | 为什么 | 反例 |
|---|---|---|
| **不与对外品牌名争夺同一个词** | 代号若好听，团队会不自觉地把它推到对外，造成"代号即品牌"的双重身份 | 内部把新产品叫 `Nova`，发布时真名叫 `X`，销售资料长期混用 |
| **不用真实人名/客户名** | 泄露合作伙伴、引发不当联想、离职后难以维护 | `Project-Karen`（指向某客户） |
| **不做语义承诺** | 代号若暗示功能，会让团队对范围产生错误预期 | `ProjectAtlas`（暗示"支撑一切"），结果只做了导出 |
| **可拼读、可搜索、无脏话** | 代号在会议、issue、代码分支里高频出现 | `Xq7` 念不出；`Fuk` 有歧义 |

## 2. 可用的题材（按"低语义承诺"排序）

1. **地名/城市**（不指向功能，易念）——注意不要用有政治/争议含义的地名。
2. **自然物**（河流、星座、矿物）——低承诺，但要避开已被大量使用的（`Nova`、`Orion`、`Titan`）。
3. **内部玩笑/典故**——记忆度高、团队认同强；**但必须过"外部听到会不会尴尬"这一关**。
4. **版本序号体系**（`v1`、`R2`）——零语义、零歧义，适合纯工程场景。

**不要用**：神话众神（早被用滥且语义宏大）、动物（易与他司撞）、颜色（跨文化含义冲突）、客户/竞品相关词。

## 3. 版本/发布代号（release codename）

- **用途**：让"哪个版本"在口头沟通中唯一可指（"上个代号那片区域出问题"）。
- **规则**：同一系列用**同一主题**（水果→字母序、山脉→首字母序），便于排序与记忆；跨系列要显式换主题，否则会混。
- **与语义化版本共存**：代号是**别名**，机器可读的版本号（SemVer）才是契约；两者不可互换（见 `code-style.md` §10 的三档重命名：版本号属"不要动"）。
- **退役机制**：发布后代号应逐步淡出（对外只用版本号），否则会沉淀成第二个品牌。

## 4. 代号 → 正式名的迁移（最容易出事的一步）

| 阶段 | 动作 | 陷阱 |
|---|---|---|
| 立项 | 代号 + 一句话范围 | 代号被写进代码仓库名/包名/数据库名 |
| 开发中期 | 正式名确定（走完整 product 流程） | 推迟到发布前才起名 → 只能选"安全但平庸"的名字 |
| 发布前 8 周 | **改名窗口**：包名/仓库/域名/文档/API | 代号残留在 API 字段与配置键里，成为永久技术债 |
| 发布后 | 代号降级为"历史别名"，只出现在 changelog | 销售/支持文档仍用代号 → 客户学会错的名字 |

**判断**：**代号不要进代码标识符**。代码里用功能名（`export-pipeline`），代号只出现在项目管理层（issue 标签、看板、会议）。否则迁移成本会从"改文档"变成"改契约"（对应 `code-style.md` §10.1 的 risky 档）。

## 5. 内部工具 / 平台组件的命名（与代号的边界）

| 对象 | 该用什么 | 不该用什么 |
|---|---|---|
| 长期存在的内部平台 | **自描述名**（`billing-service`、`ingest-gateway`） | 神话名（`Whitehall` 式：UK GDS 明确把它列为反例，见 `name-types.md` §4.2） |
| 短期项目 | 代号 | 自描述名（会与长期系统混淆） |
| 功能开关 | 业务语义名（`checkout_v2_enabled`） | 代号（`nova_enabled`，半年后没人知道是什么） |
| 实验/A-B | 实验编号 + 一句假设 | 有情绪色彩的代号（会诱导确认偏误） |

## 6. 代号自检（6 项）

- [ ] 三个"是否需要代号"的问题里至少一个为"是"
- [ ] 代号不出现在任何代码标识符、包名、仓库名、数据库名、配置键里
- [ ] 不含真实人名/客户名，无脏话与政治敏感
- [ ] 能一次念对、能听写正确（电话测试同样适用）
- [ ] 已确认不会被误当成对外品牌名（团队内已明确"这是代号"）
- [ ] 有明确的退役计划（发布后 N 周内从对外材料中消失）
