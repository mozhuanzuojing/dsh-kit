# 评分 Rubric（两模式）

## A. 产品命名（满分 100，加权）
| 维度 | 权重 | 判据 |
|---|---|---|
| 隐喻/故事 | 25 | 能画出一幅画；有 15 秒起源故事；不空洞 |
| 记忆/听感 | 20 | 电话测试过；1–2 音节/4–6 字符；读说顺 |
| 差异化 | 15 | 不撞竞品；去掉修饰仍独特；不易混 |
| 可转写/搜索 | 10 | 听一遍能拼对；"[name] 教程/vs"搜得到 |
| 可用性 | 20 | 竞品/域名/包名/社媒/TM 状态（硬门槛） |
| 可延展 | 10 | 可作名词/动词/形容词；支持品牌家族；fork 友好 |

决策：≥85 强候选；70–84 可用需权衡；<70 回第 2 步换 territory（不要降标准凑数）。

**so-what 测试**：解释后对方反应——"真妙">"哦懂了">"那又怎样/没懂/不是早有了"。目标"真妙"，可接受"哦懂了"，绝不发"那又怎样"。

## B. 代码命名（可打勾，不强行打分）
- [ ] 符合项目既有约定（precedent / glossary）
- [ ] 过 S-I-D
- [ ] 函数 = A/HC/LC，动词具体，不 vague
- [ ] 布尔正向（is/has/can/should，无否定式）
- [ ] 无未认可缩写 / 无 weasel 后缀 / 非 utils·helper 模块
- [ ] 单复数正确（单值/集合）
- [ ] 无语境重复、无冗余类型词
- [ ] 时间/单位/度量显式
- [ ] 与同文件近名不冲突（同名异义已区分 / 同义已统一）
- [ ] split test：一个函数能叫出一个动词

分档给 review 意见：**Critical**（误导/歧义/不一致，必改）、**Major**（缩写/vague/weasel，应改）、**Minor**（可读性优化，建议）。
