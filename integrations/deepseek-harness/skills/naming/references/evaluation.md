# 评分 Rubric（两模式）

> 关键结构：**否决门 → 单轴排序 → 加权打分** 三段式，不是一上来就加权求和。
> 理由：命名是**合取型**决策（一个致命缺陷就出局），加权会让"拼写灾难被三项高分抵消"。标注见 `sources.md`。

## A. 产品命名

### A1 第一层：否决门（任一命中即淘汰，不进入打分）

沿用 `anti-patterns.md` 的五宗罪与 AI slop，再加命名业界的七条否决项（SCRATCH，Alexandra Watkins《Hello, My Name Is Awesome》）：

| 否决项 | 判定问题 |
|---|---|
| **S**pelling 拼写可疑 | 说一次，对方能拼对吗？需要逐字母解释吗？ |
| **C**opycat 跟风 | 听起来像品类里已有的大牌吗？ |
| **R**estrictive 自我限制 | 会挡住未来 3 年的品类扩张吗？（如 `X for Realtors`） |
| **A**nnoying 惹人烦 | 客户愿意在电话里/会议上说这个名字吗？ |
| **T**ame 平庸 | 换成任意一个竞品还成立吗？ |
| **C**ursed 被诅咒 | 有负面联想、谐音、文化禁忌、已倒闭公司同名吗？ |
| **H**ard 难念 | 目标用户里有一半念不出/念错吗？ |

> SMILE（Suggestive / Meaningful / Imagery / Legs / Emotional）在这里**不进否决门**，它是加分维度，见 A2。
> 出处：Watkins 的 SMILE & SCRATCH，见其命名公司 Eat My Words <https://eatmywords.com/> 与书《Hello, My Name Is Awesome》（二手转述：<https://mena.entrepreneur.com/marketing/how-to-choose-a-name-for-your-company>）。

**门槛规则**：否决门命中 ≥1 条 → 弃，不进打分；存活者才从 A2 开始。

### A2 第二层：单轴排序（先粗排，再细算）

按 **Distinctive（差异化）** 单轴粗排一次，砍到 8-10 个。理由：差异化是唯一"再多分也补不回来"的维度——名字与竞品撞车时，其他维度全部失效。

> **与 A3 权重的关系（别误读）**：差异化在这里是**排序轴 + 否决级**（撞上直接进 A1 的 copycat 否决），所以它在 A3 里只值 15 分**不代表它不重要**——它已经在前面被强制执行过一次。A3 的 15 分衡量的是"除已否决的撞车之外，还剩下多少独特性余量"。若某候选在 A2 里靠后，不要指望 A3 的 25 分隐喻把它救回来。

### A3 第三层：加权打分（满分 100，只对存活者）

**先定主 KPI**：命名不是审美题，是"记忆 / 好感 / 可拼写 / 可保护"四者互相拉扯的取舍题。开场就让用户选**最多 2 个**主 KPI，其余明确标为让步项；没选就按场景默认（消费品牌＝记忆+好感；B2B＝可拼写+可保护；内部系统＝可拼写+可搜索）。主 KPI 决定下面权重的调整方向。

| 维度 | 权重 | 0 分 | 1 分（弱） | 2 分（合格） | 3 分（强） |
|---|---|---|---|---|---|
| **隐喻/故事** | 25 | 无语义，讲不出为什么叫这个 | 能编一个但牵强 | 15 秒能讲清，有具体意象 | 一听就懂又有一层可展开的余味（"真妙"） |
| **记忆/听感** | 20 | 电话测试失败，需逐字母 | 说两遍才能记住 | 说一遍能复述、能拼对 | 说一遍就记住，且能当动词/形容词用 |
| **差异化** | 15 | 与直接竞品近似 | 同类里有相似名 | 品类内独特 | 跨品类也能占住，无近名 |
| **蓝链可搜索性** | 10 | 搜不到/被通用词淹没 | 要加限定词才搜到 | 私密窗口搜索首页能定位 | 搜索结果里有独占位、无同音混淆 |
| **生成式可提及性**（可选，见 `ai-era.md`） | 0–10 | 45 次观测 0 次被提及 | 偶发提及、无引用 | 稳定提及（≥3/15），偶尔前三 | 稳定提及 + 被引用；**永远不写成"排名"** |
| **可用性** | 20 | 关键平台不可用 | 主平台可协商 | 主平台可用、次要平台需变通 | 域名/包名/handle 全绿 |
| **可延展** | 10 | 只能描述当前功能 | 扩品类会别扭 | 可支持 2-3 条产品线 | 可支撑品牌家族与子品牌 |

**权重合计**：上表基础权重合计 **100**；"生成式可提及性"是可选的 +0–10，默认关闭。打开它时要么把总分改成 110 并在呈现里写明，要么把其他维度按比例归一——**不许**出现"满分 100 却加了第 7 项"的账。

判分口径：**先各自独立打，再对照**。禁止"先定结论再补分"（这也是 agent 自评最常见的作弊，见 `SKILL.md` 的"Do not"）。

**怎么用权重**：权重是**默认值**，不是真理。场景一改就改权重——内部系统把"蓝链可搜索性"提到 20、"隐喻/故事"降到 10；消费品牌反之；如果买家主要在 AI 助手/生成式搜索里发现产品，把"生成式可提及性"从 0 提到 10–15，同时把"蓝链可搜索性"降到 5。改权重必须写在输出里，让用户看见你换了目标函数。

**分档**：≥85 强候选；70–84 可用需权衡；<70 回第 4 步（隐喻）换 territory（**不降标准凑数**）。

### A4 语境句子测试（填分数之前的现实检查）

把名字塞进真实句子里，读出来别扭就是别扭：

1. **介绍**："This is ___, it helps you ___."
2. **解释**："So how does ___ handle ___?"
3. **日常**："I'll check ___." / "Put it in ___."
4. **营销**："___ — the ___ that ___."
5. **口碑**："You should try ___."（对方会不会追问"怎么拼？"）

任一格读起来像广告腔或需要停顿解释 → 该维度扣分，不许用"习惯了就好"糊过去。

### A5 24 小时测试

呈现后建议用户隔 24h 再定：**睡一觉还记得的名字**才有资格进决赛。理由：命名的最大风险是"提案现场的说服力"压过"三天后的记忆"，这是经验规则，不是实验结论。

### A6 平局怎么破（按顺序）

1. **可用性更全者**胜（域名/handle/包名）。
2. **更短、更好念者**胜（音节数 → 字符数）。
3. **故事更具体者**胜（有画面 > 有道理）。
4. **类型更适配场景者**胜（见 `name-types.md` §4）。
5. 仍平：**给用户两个，别硬选**——说明差异与各自代价。

### A7 另一把尺子：Igor 的 9 维（用于交叉校验，不替代 A3）

Igor International 公开的 Blank Name Evaluation Chart 用 9 个维度各 10 分（满分 90）：**Appearance 视觉 / Distinctive 差异 / Depth 层次 / Energy 活力 / Humanity 温度 / Positioning 定位契合 / Sound 听觉 / "33" 话题性 / Trademark 商标**。

- 用它当**第二视角**：A3 打分很高的名字，如果 Appearance 或 Humanity 是 0，往往说明它"逻辑对但不像个品牌"。
- 出处：<https://www.igorinternational.com/process/blank-name-evaluation-chart.php>（原文公开，可直接引用）。

### A8 so-what 测试（最终筛子）

解释后对方反应：**"真妙" > "哦懂了" > "那又怎样 / 没懂 / 不是早有了"**。目标"真妙"，可接受"哦懂了"，绝不发"那又怎样"。

### A9 机器读者（新增，见 `ai-era.md`）

- **默认假设**：全新名字在 AI 推荐里的胜率 ≈ 0（零证据时 0/360；给一条第三方评分才到 53.1%）。所以"生成式可提及性"这一栏在**没有任何第三方证据**时必然低分，**这不是名字的错**，也不该因此扣分扣到淘汰——正确做法是把它写成"需先补证据"的待办，而不是换名。
- **名字侧能做的只有两件事**：① 不要用会被模型"按字面意思编造"的语义（Peec 2026：模型不认识时会用名字的词义补空，1/12 的描述在讲名字而不是公司）；② 让名字可被朗读/听写（AI 朗读门）。其余靠评分、评价、榜单、结构化数据。
- **纪律**：任何 AI 可见度数字必须带 `n` 与观测次数；**禁止**写"排名第 N"。

## B. 代码命名（可打勾，不强行打分）

- [ ] 符合项目既有约定（precedent / glossary）
- [ ] 过 S-I-D
- [ ] 函数 = A/HC/LC，动词具体，不 vague
- [ ] 布尔正向（is/has/can/should，无否定式）
- [ ] 无未认可缩写 / 无 weasel 后缀 / 非 utils·helper 模块
- [ ] 单复数正确（单值/集合）
- [ ] 无语境重复、无冗余类型词
- [ ] 时间/单位/度量显式
- [ ] 与同文件近名不冲突（同名异义已区分 / 同义已统一）
- [ ] split test：一个函数能叫出一个动词

分档给 review 意见：**Critical**（误导/歧义/不一致，必改）、**Major**（缩写/vague/weasel，应改）、**Minor**（可读性优化，建议）。

### B1 代码侧打分只在一个场景用

当用户要"在 3 个候选里选一个"时，才用：**意图准确 40 / 一致性 30 / 简洁 15 / 可搜索性 15**。否则只给定性分级——代码命名不该被一个假精确的分数决定。

## C. 两条反教条提醒

1. **讨喜 ≠ 易记**：Hodges, Estes & Warren (2024, JCR) 用 820 条真实口号 + 实验室 + 眼动 + 田野证明：更**流畅**（更短、不含品牌名、高频词、抽象）→ 更讨喜但更难记；更**易记**（更长、含品牌名、低频词、具象词）→ 相反。这是**五个变量的独立效应**，不是"具象 vs 抽象"二元轴。所以：**先定这一轮要的是喜欢还是记住**，别用"大家都喜欢"当唯一目标。
2. **分数是排序工具，不是质量证明**：85 分的名字不等于好名字，只等于"在这一套判据下更靠前"。呈现时必须同时给风险与让步项。
