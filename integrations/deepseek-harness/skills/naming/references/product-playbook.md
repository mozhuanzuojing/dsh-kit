# 产品命名 Playbook（product 模式）

## 第 1 步 · 命名简报（不建简报不生成）
问清：① 做什么（一句话）② 给谁 ③ 什么调性（技术/温暖/俏皮/权威）④ 是否品牌家族 ⑤ 禁用词/概念/风格 ⑥ 目标平台（域名 / npm / GitHub / 应用商店 / 社媒 / TM）。→ 模板见 `templates/naming-brief.md`。用户已贴简报则直接用。

## 第 2 步 · 隐喻探索（先想"什么和它像"）
**6 个找隐喻的问题**（对"简化核心功能"逐条问）：
1. 它在物理世界像什么工具/角色？（哨兵、码头工人、保险库）
2. 它对用户是哪种关系？（向导、教练、守门人、副驾）
3. 它的核心动作像什么自然过程？（涌流、生长、点燃、净化）
4. 它解决的是哪种"痛"？痛的反面是什么意象？
5. 它在神话/历史/科学里对应哪个原型？
6. 有没有一个外语词恰好精确表达（kaizen/hygge/saudade）？

**起步 territory 地图**：守卫/看护、容器/仓储、路径/导航、工具/工艺、自然/元素、生物/生态、音乐/节奏、建筑/结构、神话/占星、拟人角色、外来语根（拉丁/希腊/日/意）。
选 2–3 个 territory。简报明确时可自主选，不必让用户选；简报模糊或方向等价时才让用户挑。

## 第 3 步 · 生成候选（内部，30–50 个，不展示）
方法：territory 单词 / 双词复合 / 变形（截断、混拼、加后缀）/ 相关外语词 / 先声音后意义（念音节找顺口的组合）。保留不完美的，能看出模式。

## 第 4 步 · 过滤（内部，砍到 ~10）
过 `anti-patterns.md`：AI slop、五宗罪、复合词陷阱、AI 产品专属坑。命中 ≥2 红旗即淘汰。

## 第 5 步 · 可用性硬核验（blocking，必做）
顺序：**先竞品冲突搜索**（"[name] [品类]" 有直接竞品＝死，立即弃）→ 再域名/包名/社媒。→ 见 `availability.md` + `scripts/check-availability.sh`。字典常见单词跳过 .com/.dev/.io 精确匹配（基本被占），直接看 get[name]/use[name] 变体与 .sh/.site。存活 <3 个 → 回第 3 步加量，**不降标准**。

## 第 6 步 · 评分（内部）
用 `evaluation.md` 的产品 rubric 加权打分 + 语境句子测试（"Let me show you how ___ handles this"）。

## 第 7 步 · 呈现（第一次给用户）
3–5 个 finalist，每个：名字 / 起源故事（15 秒）/ 为何成立（满足哪些原则）/ 可用性状态（哪些平台确认、哪些需变通）/ 风险 / tagline。建议用户 24h 后再定。

## 三个硬测试
- **电话测试**：说一次 → 对方能复述、能拼对、24h 还记得。需逐字母拼＝坏。
- **15 秒故事**：讲不出"为什么叫这个"＝回去重做隐喻。
- **缩短测试**：若必然被缩写，缩写是否还好看（Kubernetes→K8s 可以）。

## 长度甜区（产品侧）
1–2 音节最优；单词 4–6 字符理想；生造词 ≤7 字符；>3 音节会被缩写。
